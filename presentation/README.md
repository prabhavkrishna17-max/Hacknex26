## How it was generated

All tooling lives in this folder. Nothing was added to the application's dependencies, and no application code was changed.

```bash
cd presentation
npm install                      # pptxgenjs 3.12.0, puppeteer-core 23.11.1 (local to presentation/)
python verify_demo.py            # uploads data/demo/demo_contract.md to the running API (in memory) and records answers
node capture_screenshots.js      # real screenshots via installed Microsoft Edge (frontend :3000, backend :8000)
node capture_demo.js             # unseen-contract screenshots (run verify_demo.py first)
node render_logo.js              # brand mark PNG
node build_deck.js               # writes the .pptx and applies the theme colours
powershell -File render_with_powerpoint.ps1   # PNG renders + PDF via installed PowerPoint
```

On this machine, run the Edge-based scripts from PowerShell: the bash sandbox blocks the browser launch. `lib/apply_theme.js` (the step that writes the palette into the deck theme) comes from Anthropic's pptx skill, which is not licensed for redistribution, so it is git-ignored and not in this repository. Without it, `build_deck.js` still builds the deck but skips the theme-colour step; the committed `.pptx` already has the theme applied.

**Quality checks performed**

- Rendered every slide with Microsoft PowerPoint and inspected it for overflow, overlap, contrast and alignment.
- Ran the pptx skill's OOXML validator: "All validations PASSED".
- Confirmed 12 slides and 12 notes pages, with no placeholder text.

### Stated with caveats on the slides

- **Groundedness, usefulness and recall are heuristics.** Groundedness and usefulness are lexical measures (quote match plus token overlap), not entailment, and recall is measured at the document level. They appear only in appendix A1, marked with an asterisk.
- **The stress-test and ablation numbers come from the extractive generator on the 8 Oct code snapshot, not the LLM.** The abstention figure has a fixed denominator of 3.
- **The live demo checks used the extractive path.** On 9 Oct, `generated_by` was `extractive_fallback`, so Gemini was not answering at capture time; the most likely cause is the free-tier daily quota on `GEMINI_API_KEY`. The slide says so.
- **The fluent answer on slide 2 is illustrative.** The slide labels it as such.

### Deliberately not claimed

- **No market statistics, time savings, accuracy against lawyers, customers or compliance certifications.** None are measured or sourced.
- **No DOCX or OCR support.** The backend has no DOCX parser, and the deck says "PDF, TXT, Markdown only". The UI's DOCX claim has since been removed (commit `3d17e56`).
- **No automatic conflict detection.** The rule-based conflict check runs but its result is not passed into the answer state; a `CONFLICTING` answer only appears if Gemini classifies it that way. The deck lists this as a limitation.
- **No claim that quotes prove claims.** An exact quote shows the text exists, not that the answer built on it is correct.

## Issues found during the audit

These were found while preparing the deck. Items 2 and 3 have since been fixed in commit `3d17e56`; the rest are still open.

1. **The problem statement file doesn't match the brief.** `docs/PROBLEM_STATEMENT.md` describes grounded QA over telemetry and regulatory specs and has no judging weights. The deck uses the title HNX26EPS01 "Agentic Legal Assistant" and the weights (groundedness 35%, retrieval 20%, usefulness 20%, research 25%) from the team's brief, which are not in the repository.
2. **Fixed in `3d17e56`:** the evidence badge now reflects `citation.verified` (previously always "✓ Checked against source").
3. **Fixed in `3d17e56`:** the landing-page examples now quote real corpus clauses (DOC-006 §9.2, DOC-008 §3.1) instead of text that was not in the corpus.
4. **`docs/PHASE3_ABLATION_RESULTS.md` disagrees with the ablation JSON.** It says STRESS-021 and STRESS-008 became SUCCESS; `full.json` says they did not. The deck uses the JSON.
5. **Clause expansion can reach outside the scoped document.** `cpde.py` falls back to other documents, so a doc-scoped query can pull in a clause from another file.
6. **Fixed in this commit:** `requirements.txt` now lists `fastapi`, `uvicorn`, `pypdf` and `python-multipart`.
7. **The payment-terms question gives an incomplete answer.** On UNSEEN-LOGISTICS-001 it returned the overdue-interest sentence but missed the 30-day payment term; avoid it in the live demo.
8. **The drafting "spoilage" preset doesn't match its default document.** It targets DOC-008 while its remedy text cites the logistics contract; select UNSEEN-LOGISTICS-001 before demoing drafting.

## Live demo runbook

The same steps are in the slide 5 notes.

1. **Set up.** Start the backend on :8000 and the frontend on :3000. In Contract Workspace, click "+ Add document", upload `data/demo/demo_contract.md`, then select "Commercial Logistics and Cold-Chain Master Agreement".
2. **Ask the cross-clause question:** *Is the service provider liable for spoilage of temperature sensitive goods when customs detention delays delivery?*
   - Expect **SUPPORTED**, with §2.3 / §2 / §5 as sources and the Related provision box linking §2.3 and §2.2.
3. **Ask the out-of-scope question:** *What are the aircraft hangar maintenance guidelines and hazardous chemical disposal protocols?*
   - Expect **INSUFFICIENT**, 0 citations, and the "Evidence Not Found — Refusal to Speculate" box.
4. **Backup question:** *What is the standard delivery window for freight consignments?*
   - Expect §2.1 "forty-eight (48) hours".
5. **If the system is unreachable,** use appendix slide A2, which shows real screenshots.
